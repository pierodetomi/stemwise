### Anticipated doubts

- **`matchering` stalled in 2022.** Compatibility with numpy 2.4 not declared; from the source it does not use removed
  APIs (`np.float`, `np.int`), but this is seen only by installing it (step 1).
- **48 kHz "not tested".** The library warns for internal frequencies other than 44,100; the source scales FFT, windows
  and limiter with the frequency, so the risk is low. The approach test runs at 48 kHz; the equivalence one at 44.1.
- **True peak above −1 dBTP** (Q-63). The `matchering` limiter looks at the sample peak: with strong commercial references
  the warning will be the norm. The PRD asks for the warning, not the correction; if by ear or for use the master must be
  within −1 dBTP, option (b) is a parameter.
- **Master distance.** `matchering` corrects the average spectrum with a FIR, our 8 bands measure the active parts: the
  distance after the master should drop a lot, but not to zero. It is information, not a threshold.
- **Infrasound and level** (emerged in step 2). `matchering` matches the full-band RMS, including the energy below 20 Hz
  that the LUFS ignores: a mix or a reference with a lot of rumble below 20 Hz would give a master more or less loud than
  the reference. On real material this is usually small (and the plan has per-stem high-passes); the
  `master_report.json` reports both LUFS values, so it shows.
- **Time.** The LOWESS leveling of `statsmodels` and the FFTs on a 4-minute track: estimated 10 to 60 s, to measure in
  manual validation.

### Doubts and risks

- **True peak above −1 dBTP** (D-074): the `matchering` limiter works on the sample peak (≈ −0.02 dBFS), so with a strong
  commercial reference the warning will be the norm. The PRD asks for the warning, not the correction; if you need a
  master within −1 dBTP, option (b) of Q-63 is a parameter (`Config.threshold`).
- **Infrasound and level** (emerged in step 2): the library matches the full-band RMS, which counts the energy below 20 Hz
  ignored by the LUFS. On 1/f pink noise down to 0.1 Hz the master came out 1.9 LU above the reference, while with the
  noise filtered at 20 Hz the gap is 0.02 LU. On real material this is usually small; the report shows both LUFS values,
  so it is visible.
- **48 kHz "not tested"** by the library (D-070): the source scales FFT, windows and limiter with the frequency, and the
  approach test runs at 48 kHz, but the equivalence with the documented API is verified only at 44.1 kHz.
- **Library stalled in 2022**: the import of `scipy.ndimage.filters` will disappear with SciPy 2.0. Now only `master`
  touches it (deferred import); `scipy` is not pinned at the top level.
- **Deviations from the plan**:
  - tolerances of the approach test tightened to 0.3 dB and ±0.3 LU (plan: 1.0 dB and ±1 LU), about ten times the
    measured values (review finding 6);
  - `--run` with `--mix` exits with code 1 and not 2: it follows the rule already in use for incompatible `mix` options
    (`--baseline-only` with `--plan`); 2 remains for parser errors (unknown option) (finding 7);
  - tests added beyond the plan: `test_reference_is_mandatory`, `test_input_rates`, `test_master_run_files`,
    `test_other_commands_do_not_import_the_library`, `test_mono_inputs_are_measured_as_mastered`,
    `test_true_peak_ok_uses_full_precision`, `test_master_true_peak_warning_reaches_the_cli`.
- **Measurements on the re-read file** (D-076): no test tells them apart from those in memory. At one decimal the
  difference of 24-bit quantization is not visible (finding 9, only noted).
