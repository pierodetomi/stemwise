# DSP processors

Documentation of the processors of the `stemwise-dsp` crate (FOUNDATION §5.7: every processor without an oracle is
described here with algorithm, parameters and verified properties). The text of each section is the module comment of
the source file, in English like the code; this file is regenerated by copying it.

Common conventions: internal computation in f64 (f32 in the oversampling, A-022), f32 output; no allocation, lock
or I/O in `process` (verified by `crates/stemwise-dsp/tests/no_alloc.rs`, NFR-2); parameters updatable every 32
samples (`util::SUBBLOCK`) with per-sample smoothing, hence a result independent of the block size
(ENG-4). Parity with the PoC oracle: biquad and pan (±0.01 dB), integrated loudness and LRA (±0.1 LU), true peak
(±0.1 dB; measured within 0.01 dB) on all the cases in `app/fixtures/oracle`.

## Biquad RBJ (FX-2)

RBJ biquads (FX-2): the same formulas as the PoC (poc/docs/analysis.md, "Filters and EQ").

## Compressor (FX-3, MAS-1)

Source: [`compressor.rs`](../../app/crates/stemwise-dsp/src/compressor.rs).

Feed-forward compressor with a stereo-linked detector (FX-3, MAS-1; closes D-034 of the PoC).

- Detector: per sample, the larger absolute value over the channels of the key signal (the processed signal
  itself, or a sidechain source through a Butterworth high-pass). One detector for both channels: stereo is
  compressed in a linked way.
- Gain computer (in dB) with a soft knee of width `W` (Giannoulis, Massberg & Reiss 2012):
  below `T − W/2` no change; above `T + W/2`, `T + (x − T)/R`; in between the quadratic
  `x + (1/R − 1)(x − T + W/2)² / (2W)`.
- Ballistics: smoothed gain reduction in dB, branching one-pole: attack coefficient `exp(−1/(τa·fs))` when the
  reduction grows, release `exp(−1/(τr·fs))` when it shrinks.
- Makeup: a gain after the compressor, smoothed per sample (20 ms) so changes do not click.
- Mix (dry/wet, tracks and groups; P-011): the output gain is `1 + mix·(g − 1)`, that is `x·(1 − mix) + x·g·mix` on the
  same sample, so the dry and the compressed signal never comb. Smoothed like the makeup. At 1 the code path is the
  one without a mix; the master compressor is always at 1.
- Meter: the deepest reduction since the last `take_gr_db`.
- Detector high-pass filter (MAS-13): without a sidechain key, `detector_hpf_hz > 0` makes the detector listen to the
  signal through a 2nd-order Butterworth at that frequency (own state, per channel); the audio path is not touched.
  0 disables it (default). With a key, `sidechain_hpf_hz` stays in force.
  Verified: a 50 Hz sine at −6 dBFS (threshold −20 dB, ratio 4) has at least 6 dB less reduction with 200 Hz,
  a 2 kHz sine is reduced the same way (±0.2 dB).

Properties verified by the tests: static curve and knee, attack and release times, linking, sidechain with
its high-pass, makeup, mix (0 is the input, 0.5 the mean of dry and wet at every sample, smoothed changes),
stability and block-size invariance.

## Saturation (FX-4)

Source: [`saturation.rs`](../../app/crates/stemwise-dsp/src/saturation.rs).

Soft saturation with 4x oversampling (FX-4).

**Algorithm.** Per sample: input gain `g = 10^(drive_db/20)`, shaper `y = shape(g * x) * c(g)` with
`shape(u) = 2 tanh(u / 2)` (unity small-signal slope; ceiling 2 keeps the knee soft enough for alias rejection) evaluated at 4x
through [`Oversampler4`] (257-tap Kaiser linear-phase FIR, ~90 dB stopband, see that module), then
`out = dry_delayed * (1 - mix) + y * mix`.

**Level compensation.** `c(g) = A / shape(g * A)` with reference peak `A = 10^(-18/20)` (the level of a
-18 dBFS sine), computed analytically per sample from the smoothed gain: the shaped level at the reference
amplitude equals the unshaped one. At drive 0 dB `c` is about 1.0, so low-level signals pass transparently.

**Smoothing.** `drive` (linear gain) and `mix` are smoothed per sample with a 5 ms one-pole towards the
targets set by `set_params`, independently per channel; output is therefore independent of block size.

**Latency.** [`Saturation::LATENCY`] = [`Oversampler4::LATENCY`] = 64 samples, integer; the dry path goes
through a 64-sample delay so that `mix` blends phase-aligned signals. Engine compensates it (ENG-5).

**Properties verified (tests).** Exact latency (peak and mix 0), transparency at -40 dBFS (+-0.1 dB), level
within +-1 dB for drive 0..18 dB at -18 dBFS, 3rd harmonic present at drive 18 dB, aliasing of the 3rd harmonic
of 15 kHz at 48 kHz below -60 dB, no NaN/inf at drive 24 dB on full-scale noise, block-size invariance
(<= 1e-6), independent channels. Process does not allocate, lock or perform I/O.

## Oversampling 4x

Source: [`oversample.rs`](../../app/crates/stemwise-dsp/src/oversample.rs).

4x oversampler (one channel): two cascaded 2x half-band stages, linear phase, around a nonlinear callback.

**Algorithm.** Each stage is a Kaiser-windowed half-band FIR (`h[c] = ½`, zero at the other even offsets, odd
taps `½·sinc((k − c)/2)·w[k]` normalised so they sum to ½), in polyphase form: upsampling copies the centre
sample and computes one dot product of the odd taps; downsampling computes one dot product of the odd taps over
the odd-phase history plus the centre term. Arithmetic in f32 with contiguous, multi-accumulator dot products
(vectorisable), histories mirrored to avoid modulo.
- Stage 1 (base ↔ 2x): `c = 56` odd taps (113-tap prototype), Kaiser β 8.2: passband to 20 kHz and stopband
  from 24.1 kHz at 44.1 kHz (≥ 80 dB).
- Stage 2 (2x ↔ 4x): `c = 14` odd taps (29-tap prototype), Kaiser β 7.9: only has to reject the images above
  68.2 kHz (≥ 80 dB); what folds into 20–44 kHz at 2x is removed by stage 1 on the way down.

**Latency.** Stage 1 delays by `c₁ = 56` base samples round trip, stage 2 by `c₂/2 = 7`; a 1-sample delay line
pads the total to exactly [`Oversampler4::LATENCY`] = 64 base samples, a multiple of the engine's 32-sample
parameter grid (ENG-5, A-020).

**Cost.** About 160 multiply-adds per base sample instead of ~520 for a single 257-tap 4x FIR (A-022).

**Properties verified (tests).** Identity round trip flat within 0.1 dB at 1 kHz and 18 kHz (48 kHz), impulse
peak exactly at `LATENCY`, stopbands of both stages ≥ 80 dB, reset clears the state.

## Reverb (FX-5, FX-9)

Source: [`reverb.rs`](../../app/crates/stemwise-dsp/src/reverb.rs); test measurements in
[`revmeasure.rs`](../../app/crates/stemwise-dsp/src/revmeasure.rs). Replaces the comb reverb of the first
delivery (P-011, A-058).

Three own implementations of published designs, chosen per return (the algorithm is fixed when the graph is built:
changing it is a structural change).

- **Plate**: Dattorro's plate ("Effect Design, Part 1", JAES 1997). Mono sum → input bandwidth low-pass → 4 input
  allpass diffusers (142, 107, 379, 277 samples at 29761 Hz; 0.75, 0.75, 0.625, 0.625) → a figure-eight tank of two
  halves, each a modulated allpass (672 / 908, coefficient 0.7), a delay (4453 / 4217), a damping shelf, a second
  allpass (1800 / 2656, coefficient 0.5) and a second delay (3720 / 3163). Output: 7 taps per side across the tank.
  One departure from the paper: the four taps it takes inside the tank allpasses are taken from the delay line that
  follows each of them, because the inside of an allpass is a comb and its period was audible in the tail.
- **Room** and **Hall**: a feedback delay network of 16 lines mixed by a Hadamard matrix (lossless before the per-line
  attenuation). Lines of 6.7–40.9 ms (room) and 21.1–96.7 ms (hall) at scale 1. Fed in stereo (left on even lines,
  right on odd ones) through 2 (room) or 4 (hall) allpass diffusers, plus 6 early reflections per side taken before
  the diffusers (3–25 ms in the room, 2.4 times later and softer in the hall). Input and output sign patterns are
  *bent* sequences: their Hadamard transform is flat, so no single line comes back into the output more than the
  others (with a row of the matrix as the output pattern one line returned whole: a peak of 0.2 in the
  autocorrelation at that line's length).

Parameters (the user's ranges; the AI plan has tighter ones, FOUNDATION §5.5):

| Parameter | Range | Meaning |
| --- | --- | --- |
| `decay_s` | 0.1–10 s | RT60 at mid frequencies: every loop element of length `L` is attenuated by `10^(−3·L/(rate·decay_s))` |
| `size` | 0–1 | Scale of the loop lengths: network 0.6–1.4×, plate 0.5–1.25× |
| `damping` | 0–1 | First-order shelf at 5 kHz in every loop: the high-frequency decay is `decay_s·(1 − 0.85·damping)` |
| `modulation` | 0–1 | Slow movement (0.5–1.3 Hz, up to ±1 ms) of 4 of the 16 lines, or of the two tank allpasses |
| `predelay_ms` | 0–200 ms | Before everything else |
| `hpf_hz`, `lpf_hz` | 20–1000 Hz, 1–20 kHz | Butterworth on each output channel |

Details that matter:

- **The plate shrinks with short decays.** The sound goes around the tank at least five times within `decay_s`, so
  below about 3 s the decay sets the plate's size and `size` is only an upper bound. Measured: energy takes 1.09 times
  the sum of the tank lengths to go around once; the attenuation uses that figure.
- **Under about 1 s the plate is grainy by construction**: its tank allpasses show as a fast flutter (their impulse
  response is an echo train that only later trips around the tank diffuse). A room is the better short space; the
  interface says so under the algorithm selector and the prompt tells the model.
- **Deterministic modulation.** Recursive sine oscillators ("magic circle") with fixed starting phases, restarted by
  `reset`: no random source. Two reverbs given the same input give the same samples, and so does one reverb after a
  reset.
- **Smoothing.** Gains, damping, pre-delay and level with a one-pole (30 ms); loop lengths with a slower one (120 ms)
  that lands exactly on whole samples, so a settled reverb reads its delays without interpolation (interpolated only
  while `size` moves, and on the modulated lines).
- **Level.** The output gain follows `sqrt(scale)·decay_s^−0.25`: the return grows gently with the decay (about
  +0.75 dB per doubling) instead of 3 dB. Calibrated with stereo pink noise as the send: +2 dB over the send at 1.5 s
  for the three algorithms.
- All arithmetic in f64; state flushed so tails end in exact zeros. 100% wet.

**Measured** (48 kHz, impulse response; `repeat` is the autocorrelation of the flattened tail that comes back at a lag
and again at twice that lag, 2–150 ms: what a comb leaves):

| | RT60 vs `decay_s` (0.5–6 s, no damping) | `repeat` at 2 s / 4.6 s | L/R correlation of the tail |
| --- | --- | --- | --- |
| Plate | within 5% | 0.06–0.10 / 0.05 (0.13–0.3 under 1 s) | below 0.03 |
| Room | within 3% | 0.07–0.08 | below 0.11 |
| Hall | within 3% (0.3 s: +11%) | 0.05–0.06 | below 0.08 |
| Comb reverb it replaces | — | 0.16–0.20 / 0.14 | below 0.02 |

With the default damping (0.5) and modulation (0.2) the mid-band RT60 is 3–9% short (the shelf and the interpolated
reads take a little from 2 kHz).

**Properties verified by the tests (FX-9).** Decay time within ±10% of `decay_s` at 0.5, 1.5 and 4 s with no damping
(±15% at the defaults); `repeat` below 0.11 at 2 and 4 s; |L/R correlation| below 0.3 with a mono send; highs at least
20% shorter than mids at damping 0.5 and within 10% at 0; pre-delay exact to the sample; high-pass and low-pass
effective (≥ 15 dB); calibration levels (±1.5 dB) growing with the decay; exact silence after the tail; determinism
and restart on reset; the same samples with blocks of 64 and 4096; bounded output with full-scale noise at the longest
decay and with every parameter changing every 32 samples; no allocation in `process` (`tests/no_alloc.rs`). In the
engine: the same hash with blocks of 64, 1000 and 4096 with the three algorithms sending at once, and NFR-1 with four
reverbs added to the benchmark (p99 18% of the buffer period).

**Not verifiable by the agent.** How they sound: `docs/app/VALIDATION.md`, points 25–26.

## Delay (FX-6)

Source: [`delay.rs`](../../app/crates/stemwise-dsp/src/delay.rs).

Stereo delay return (FX-6).

Structure (f64 arithmetic, state flushed with [`flush`] so tails end in exact zeros):
- two independent delay lines (L, R) with the same time, buffers for 2.1 s, written with
  `input + feedback · filtered(read)`; the output is the delayed signal (100% wet);
- feedback path: RBJ Butterworth (Q 1/√2) high-pass at `feedback_hpf_hz` then low-pass at `feedback_lpf_hz`;
  `feedback` is clamped to 0..0.95;
- time changes glide: the delay time (in samples) follows its target with a one-pole of about 50 ms per sample,
  and the line is read with linear interpolation at the fractional position, so sweeps do not click and the
  result does not depend on the block size. The first `set_params` call (and `reset`) snaps the smoothed time.
  Filter coefficients are redesigned in `set_params` only when their frequency changes.

Properties verified by the tests: echo position `round(time · rate)` (±1 sample), echo decay of
`20 · log10(feedback)` dB per repeat with open filters (±0.5 dB), boundedness at feedback 0.95 with full-scale
noise, no clicks while sweeping the time, block-size invariance, exact silence after the tail.

## True-peak limiter (MAS-1, MAS-3)

Source: [`limiter.rs`](../../app/crates/stemwise-dsp/src/limiter.rs).

True-peak limiter with look-ahead (MAS-1, MAS-3).

1. Detection: each channel goes through the 4x true-peak interpolator of `truepeak` (the PoC's filter); the
   detector value for a sample is the largest of its four interpolated points, over both channels.
2. Required gain `r = min(1, c / tp)`, with `c` the ceiling lowered by an internal margin of 0.1 dB (covers
   the inter-sample effect of a moving gain and 24-bit quantisation).
3. Hold: the minimum of `r` over the last `L` samples (`L` = 2 ms of look-ahead).
4. Attack: a moving average of the held value over `L` samples. Every average that includes a peak's sample
   is made of values ≤ that peak's `r`, so the gain applied to the peak (the signal is delayed by `L − 1`) is
   at most `r`: the ceiling holds by construction, with a smooth `L`-sample ramp.
5. Release: when the gain rises, it follows with a one-pole of `release_ms`; falling is never slowed.

Total latency [`Limiter::latency`] = 10 (detector) + `L − 1` samples; the engine compensates it (ENG-5).
The guarantee is checked again on the exported file (`truepeak::true_peak_db`), which the export repeats
with a lower ceiling in the rare case it is exceeded (MAS-3, MAS-10).

## Master chain (MAS-1, MAS-5; ENG-3)

Source: [`master.rs`](../../app/crates/stemwise-engine/src/master.rs) of the engine.

The chain is: input gain, 6-band EQ, match EQ, compressor, width, saturation, loudness gain, limiter, then the
listening trim. New parameters never step inside the signal:

- **Continuous values glide** every 32 samples towards their target with a 10 ms one-pole. These are the gains,
  the EQ bands (frequency and Q in the log domain; a change of band type goes through 0 dB), the match EQ gains, the
  side gain and the mono frequency.
- **Gains ramp per sample** within the 32-sample sub-block.
- **Switching a block on or off** is a cross-fade between its input and its output. The A/B against the unprocessed
  input is a cross-fade too.
  - EQ, match EQ and width glide to the identity, then stop running with their state cleared.
  - Saturation and limiter keep running when off, so a fade-in never starts from an empty oversampler or look-ahead.
  - Their dry delay lines always run, so a fade never plays stale audio.
- **With constant parameters** the glides start at their target, so offline renders are unchanged and deterministic.

Verified:

- `master_changes_glide_instead_of_stepping`: the largest step between consecutive samples after each kind of change
  stays near that of the sine itself.
- `mono_below_removes_the_side_of_the_low_end_only`: side −24 dB an octave below the crossover, mid within 1 %.

## Clipper (MAS-11)

Source: [`clipper.rs`](../../app/crates/stemwise-dsp/src/clipper.rs).

Peak clipper with 4x oversampling (the same `Oversampler4` as the saturation, 64-sample integer latency).
The shape is computed at the 4x rate on each of the four points, odd-symmetric, with threshold `T` and knee start
`a = T·(1 − 0.5·softness)`:

- `|x| ≤ a`: `|x|` (no level compensation, unity gain below the knee);
- above: `T − (T − a)·exp(−(|x| − a)/(T − a))`, continuous with continuous derivative at `a`, asymptote `T`;
- `softness = 0`: hard clip `min(|x|, T)`.

Parameters: `threshold` (linear amplitude, > 0) and `softness` (0…1), smoothed per sample with a 5 ms pole,
independently per channel; `settle` jumps to the target values. The `take_gr_db` meter gives the deepest gain applied
to a 4x sample since the last call (≤ 0 dB, 0 if nothing was clipped).

The 4x signal never exceeds `T`; after decimation the half-band filter can overshoot by a fraction of a dB
(Gibbs on a flat-topped wave): the tests allow 0.5 dB.

Verified: exact latency, transparency below the knee (±0.01 dB), peak ≤ `T` + 0.5 dB with a sine overdriven
by 12 dB, meter ≈ −6.02 dB on a known peak (±0.3 dB) and 0 below the knee, 3rd harmonic lower with
`softness` 1 than with 0, aliasing of a 15 kHz sine (48 kHz) below −50 dB, block invariance (blocks 1,
64, 1000, ≤ 1e-6), independent channels, no NaN on full-scale noise with threshold 0.01. `process` does not allocate.

## Multiband compressor (MAS-12)

Source: [`multiband.rs`](../../app/crates/stemwise-dsp/src/multiband.rs).

2–6 band compressor, zero latency. The crossover is a 4th-order Linkwitz-Riley (two cascaded Butterworth biquads per
slope) arranged as a tree: the lowest band splits off first, `band j = LP(fj)(rest j)`,
`rest j+1 = HP(fj)(rest j)`, the last band is the rest. The sum of an LR4 low-pass and high-pass at the same
frequency is the 2nd-order all-pass `(s² − √2 s + 1)/(s² + √2 s + 1)`: every band split off at `fj` therefore passes
through an all-pass (Q = 1/√2) at each later crossover frequency, so the sum of all the bands is
`AP(f0)·…·AP(f(N−2))·x`, an all-pass of the input (flat magnitude) for every number of bands.

Each band goes through a stereo-linked `Compressor` (reusing `compressor.rs`, including `mix` and
`detector_hpf_hz`); a band with `on = false` passes uncompressed; if any band has `solo`, only the
soloed bands are summed. The crossovers are limited to 20 Hz … 0.45·sampling frequency, ascending and at least 1/3
of an octave apart. Changing the number of bands clears the filters; changing the frequencies only replaces the
coefficients. All the memory for 6 bands is allocated in `new`; `process` works in blocks of 256 samples on preallocated buffers.

Verified: flat sum within ±0.1 dB between 30 Hz and 18 kHz for 2, 3, 4, 5 and 6 bands; isolation (50 Hz at −6 dBFS
compressed in band 0, reduction only there, 5 kHz mixed within 0.2 dB); solo (over 24 dB of attenuation
an octave past the crossover); band off; crossover changes between blocks without NaN; crossover limits and order;
block invariance (1, 64, 1000, ≤ 1e-6); stereo linking; no allocation
(`tests/no_alloc.rs`).

## Block chain (FX-10 → FX-12)

- **Order and latency.** The blocks of a track run in list order. Each type has a fixed latency in
  samples, a multiple of the 32 grid (saturation and the other oversampled blocks: 64). Every track and group
  chain is padded by a delay line to the latency of the slowest chain in the project; returns to the latency of the
  slowest return. The parameters of a block are evaluated at the time of the audio they touch: the node's input
  latency plus the latency of the blocks before it.
- **Bypass.** The value slides linearly over 10 ms (`FADE_S`), per sample, with state carried between the compute
  blocks: the result does not depend on their size. A fully off block is skipped, a fully on one is not
  mixed. **Whether the processor sleeps is decided once per 32-sample cell**, from the state of the fade at the
  start of the cell: the fade lasts 481 samples at 48 kHz and ends mid-cell, and deciding per piece made the frozen
  state depend on where the compute block cut the cell (A-090). A block that is turned back on **restarts from a clean
  state** (lines and filters cleared, LFO phase restored from the position): it does not play the audio it held
  when it was turned off. Verified properties: with bypass 0 → 1 → 0 on a
  low-pass, compressor, harmonizer and doubler the render is bit-identical with blocks of 4096, 64, 777, 1000 and
  from 12,481 to 12,511 (the boundary falls in the cell where the fade ends); a doubler turned off on noise and
  turned back on in silence gives exact silence. A block with latency mixes the output with its own input
  delayed by the same latency; when off it passes the delayed input.
- **Resonant filters (FX-12).** RBJ high-pass and low-pass biquads with Q = `resonance` (0.5–10; 1/√2 is the previous
  Butterworth). Verified property: at the cutoff frequency the gain is Q (−3 dB at 1/√2, +18 dB at Q 8, ±5%).
- **Mono → stereo.** The first stereo block copies the channel into the second; the final pan uses the mono law on each
  channel, so a neutral stereo block does not change the level.

## New track blocks (FX-13 → FX-24)

Common rules (FX-24), verified for every block by the tests of its module: in neutral position the signal does not change
(≤ 1e-6, apart from the constant latency); no allocation in `process` (`tests/no_alloc.rs`); result independent of the
size of the compute blocks (chunks of 32, 1000 and 7 samples, ≤ 1e-6); stable with parameters changing
every 32 samples; bounded output with full-scale noise. In the engine: all blocks in neutral position leave the
render identical; a chain with all the blocks at work does not depend on the compute block; modulation, tremolo and
tape delay give from second 4 the same samples as the full render (≤ 1e-4: the phases accumulate per sample from a
different anchor point, the rounding differs by a few 1e-5). Latencies: saturation, clipper, exciter and
bass enhancer 64 samples; harmonizer 864 at 48 kHz (35 ms window, a multiple of 32); all the others 0.
Benchmark (FX-24): 32 tracks with the classic chain and 8 with harmonizer, four-band multiband and chorus: callback p99
27% of the period (threshold 50%).

### Gate / expander (FX-13)

Detector: maximum of the absolute value over the channels of the key (the signal itself or the sidechain: **all** the channels of the key even when the signal is mono, so a source entirely on the right still opens it; this holds for the dynamic EQ too, A-090), through 2nd-order Butterworth high-pass and low-pass (20 Hz and 20 kHz = off), then a peak follower (instant attack, 10 ms decay). Curve (dB): above the threshold 0 dB; below `−(ratio − 1)·(threshold − level)` limited to `−range` (at ratio 20 it reaches the range). Hold: after dropping below the threshold the gain stays at 0 dB for `hold_ms`. The gain in dB follows the target with a single pole per sample (`attack_ms` when opening, `release_ms` when closing). Latency 0; meter: deepest gain since the last `take_gr_db`.

Parameters: threshold, range 0–80 dB, ratio 1–20, attack 0.05–50 ms, hold 0–500 ms, release 5–2000 ms, HPF 20–2000 Hz, LPF 1–20 kHz.

Verified properties: steady state below the threshold = −range ±0.5 dB (sine at −60 dBFS, threshold −30, range 40); above the threshold unchanged (difference ≤ 1e-4 after 100 ms); range 0 = identity (≤ 1e-6); the sidechain key opens the gate (±0.1 dB) while without a key it closes (< −39 dB); a 200 ms hold keeps it open, then it closes at −range ±0.5 dB; meter ≈ −range ±0.5 dB; same result with blocks of 32, 1000 and 7 (≤ 1e-6); full-scale noise with parameters changing every 32 samples: finite and |output| ≤ |input| (the gain does not exceed 0 dB).

### De-esser (FX-14)

Split: `high = x − LP(x)`, with a 2nd-order Butterworth LP at the chosen frequency; the frequency is smoothed (single 20 ms pole) on a 32-sample grid counted from `reset`, hence independent of the block. Detector: `high` through a 2nd-order Butterworth high-pass at the same frequency (the complement alone drops 6 dB per octave: a loud vowel at 2 kHz reached a 6 kHz detector just 6 dB down and pulled the highs down without any sibilants; with the high-pass it is 25 dB down, A-090), then its power (maximum across the linked channels), with 1 ms attack and 60 ms release; level = `10·log10(power) + 3.01 dB` (peak of a sine in the band). Reduction: ratio 10 beyond the threshold, limited to `max_reduction_db`, smoothed (2 ms). `Split`: `y = x − (1 − g)·high` (below the frequency the level does not change: the complement of the low-pass is a 1st-order high-pass in quadrature, at 500 Hz with corner 6 kHz it sits 19 dB down and the level error is < 0.05 dB). `Wide`: `y = g·x`. `listen`: the output is `high` only. Latency 0.

Parameters: frequency 3–12 kHz, threshold, maximum reduction 0–12 dB, mode, listen.

Verified properties: a 2 kHz tone at −12 dBFS with corner at 6 kHz and threshold −30 produces no reduction (> −0.1 dB), an 8 kHz one does (< −6 dB); in Split a 500 Hz tone with a loud 8 kHz (reduction ≥ 4 dB) keeps its level within ±0.1 dB while the 8 kHz drops ≥ 4 dB; Wide lowers both the same way (±0.1 dB); maximum reduction 0 = identity (≤ 1e-6) in both modes; the reduction does not exceed the maximum; listen: 500 Hz ≤ −15 dB, 8 kHz within ±3 dB; block invariance with a moving frequency (≤ 1e-6); full-scale noise with varying parameters: finite, |output| ≤ 4.

## Dynamic EQ (FX-15, `dyneq.rs`)

**Algorithm.** Up to two bands (`Peak`, `LowShelf`, `HighShelf`). For each band a *detector* filters the key
(the band's sidechain, or the signal itself) with the shape of the band: band-pass at 0 dB peak at `freq_hz`
with the band's `q` for `Peak`, Butterworth low-pass (low shelf) or high-pass (high shelf) at `freq_hz`. The
absolute values of the channels are linked (maximum) and followed by a peak follower with one-pole attack and release.
With `over = level_dB − threshold_db` the target gain is `range_db · clamp(over / 6, 0, 1)`: **the band reaches the
full range at 6 dB above the threshold** and at or below the threshold it is exactly 0 dB. The gain is smoothed (2 ms pole) and
applied as an RBJ biquad (peak, low shelf, high shelf). Below 1e-4 dB with target 0 the gain snaps to exactly 0 and
the filter is the identity (the band moves **only** when the detector exceeds the threshold, FX-24). Frequency and Q of
the output filter are smoothed (5 ms, in log) on the coefficient grid, so that high-Q automation does not
blow up the biquad.

**Parameters.** `on`, `shape`, `freq_hz`, `q` (0.1–10), `threshold_db`, `range_db` (−12…+6: negative cuts, positive
boosts), `attack_ms`, `release_ms`. `take_gain_db()` returns per band the gain of largest magnitude (signed)
since the last call.

**Latency.** 0 samples. The coefficients are recomputed every 32 samples counted from `reset` (independence from the
block size); envelope and gain are per sample.

**Verified properties.**
- 3 kHz tone below the threshold: identity (≤ 1e-6) and `take_gain_db` = 0;
- 14 dB above the threshold with range −6: the 3 kHz drops 6 dB (±0.5), a mixed-in 300 Hz stays unchanged (±0.1 dB);
- range +4: the boost is +4 dB (±0.5);
- with the key: the 3 kHz guitar drops 6 dB (±0.5) only while the key burst is loud, after the release it is
  identical to the input (≤ 1e-6); with a silent key it is identity (≤ 1e-6);
- low shelf: cuts 100 Hz by 6 dB (±0.7) and leaves 5 kHz alone (±0.2 dB);
- neutral (range 0 or bands off): identity ≤ 1e-6;
- block independence (32, 1000, 7): difference ≤ 1e-6;
- full-scale noise with +6 dB, Q 10, zero times: finite and |y| ≤ 16 (two bands in series, generous threshold);
- parameters changing every 32 samples on noise for 3 s: finite and |y| ≤ 64.
`process` does not allocate, take locks or do I/O.

### Transient shaper (FX-16)

No threshold, all on ratios. Base envelope: peak follower of the absolute maximum across channels (instant attack, 10 ms decay). Two single-pole followers of the envelope: fast (`4 ms·0.15^speed`) and slow (`40 ms·0.3^speed`). `d = 20·log10(fast/slow)`: attack part `d` beyond a dead zone of 1.5 dB (full at 10 dB), sustain part `−d` beyond 0.5 dB (full at 6 dB). Gain in dB = `attack_db·w_att + sustain_db·w_sus`, smoothed (0.25 ms), then `y = x·(1 − mix + mix·g)`. Latency 0. A steady tone has weights 0 (fast = slow).

Parameters: attack ±12 dB, sustain ±12 dB, speed 0–1, mix 0–1.

Verified properties: a steady sine (200 Hz and 1 kHz, speed 0 and 1, all ±12 dB combinations) does not change level (±0.1 dB); with attack +6 dB the peak of the first 15 ms of a burst rises ≥ 3 dB, with −6 dB it drops ≥ 3 dB; the gain curve at −30 and −6 dBFS matches within 0.5 dB; attack = sustain = 0 or mix 0 = identity (≤ 1e-6); block invariance (≤ 1e-6); full-scale noise with varying parameters: finite, |output| ≤ 16.

## Color (FX-18): saturation character, exciter, bass enhancer

### Saturation character (`saturation.rs`)

`SaturationParams` has the field `character`: `Soft`, `Tape`, `Tube`, `Transistor`. `Soft` is the original algorithm,
bit for bit (existing projects keep their render hash). The others use the same 4x path, the same level
compensation (reference level −18 dBFS, computed on the character's static curve) and the same
64-sample latency.

- **Tape**: soft curve, then a one-pole low-pass at 12 kHz (at the 4x rate) in the wet path only: the gentle
  roll-off of the highs.
- **Tube**: asymmetric: bias 0.3 (in units of the ceiling) before the soft curve, bias response removed and slope
  restored to 1, then a one-pole high-pass at 10 Hz (4x) that removes the DC component. Even harmonics dominate.
- **Transistor**: `u / (1 + u^4)^(1/4)`, ceiling 1: hard knee, odd harmonics, brighter than `Soft`.

The change of character is not faded (it is a discrete choice, not an automation target).

Verified properties: `Soft` identical to a checksum recorded before the change; Tube with the 2nd harmonic ≥ 10 dB above
Soft (and > −50 dB on the fundamental); Transistor with the 3rd harmonic ≥ 3 dB above Soft (drive 18); Tape ≥ 1.5 dB below Soft at
10 kHz and within 0.3 dB at 1 kHz; level within 1.5 dB for drive 0…18; aliasing < −50 dB (15 kHz, drive 18); mix 0 = delayed
dry (≤ 1e-6); bounded (< 4) on noise at drive 24; Tube with no DC (< 2e-3); block invariance (7, 32, 1000)
≤ 1e-6; stable with parameters every 32 samples.

### Exciter (`color.rs`)

`HP(freq)` 2nd-order Butterworth → saturation `2 tanh(g u / 2)` at 4x with level compensation → `HP(freq)`
again → `× amount`, summed to the dry delayed by 64 samples. The two high-passes rotate the band by 180° at the
cutoff frequency (it would come back as `−0.5·x` and dig a hole of up to 6 dB): the **band-pass of the delayed dry**
at the same frequency, `BP = 1 − LP − HP` with Q 1, also times `amount`, is therefore added to the generated part
(A-090). With this the real part of what is summed is never negative (up to the small-signal gain of the saturation at
drive 24, 1.31) and the response never drops below the dry; the price is a boost that
starts about an octave below the frequency. Parameters: `freq_hz` 1000…12000, `drive_db` 0…24, `amount`
0…1. Latency 64 (`Exciter::LATENCY`). Drive and amount smoothed per sample (5 ms); `freq` smoothed and filters redesigned
every 32 samples counted from `reset` (block independent).

Verified properties: `amount` 0 = delayed dry (≤ 1e-6); with `amount` 1 a sine from two octaves below to two above the
frequency never comes out lower than it went in (> −0.05 dB, at drive 0 and 24); a 200 Hz sine with corner at 3 kHz
gains < 0.1 dB even at drive 24; a 6 kHz sine gains > 3 dB; the harmonics appear (3rd at 12 kHz > −50 dB); bounded (< 5) on noise;
block invariance ≤ 1e-6; stable with parameters every 32 samples.

### Bass enhancer (`color.rs`)

The delayed signal goes through `LP(freq)` (2nd order); a peak follower (instant attack, 200 ms release)
normalizes it to [−1, 1]; the harmonics are `env · (0.5 T2 + 0.35 T3 + 0.15 T4)` (Chebyshev polynomials: for a sine
exactly the 2nd, 3rd and 4th harmonics, without the fundamental, with the level following the input); then a 4th-order
`HP(freq)` (two biquads) so that nothing below `freq` is added, nothing an octave below (the DC of T2 is removed too);
scaled by `harmonics · mix` and summed to the delayed dry. Without oversampling: the harmonics stay below 4 ×
`freq` ≤ 640 Hz. Parameters: `freq_hz` 40…160, `harmonics` 0…1, `mix` 0…1. Latency 64 (`BassEnhancer::LATENCY`).

Verified properties: `mix` 0 or `harmonics` 0 = delayed dry (≤ 1e-6); on a 60 Hz sine (corner 100 Hz) 120 and 180 Hz
> −35 dB on the fundamental and DC, 20, 30, 40 Hz < −60 dB; the harmonics scale with `harmonics` (half = −6 dB ±1);
bounded (< 3) on noise; block invariance ≤ 1e-6; stable with parameters every 32 samples.

## Motion: modulation, tremolo/autopan and width (FX-19, FX-20, FX-24)

**Phase rule (FX-20).** The phase of every LFO depends only on the position in the song: `process` receives `pos`, the
timeline frame of the first sample. The processor keeps `next_pos`; if `pos != next_pos` (first call after
`reset`, jump, loop) the phase becomes `frac(rate_hz · pos / rate)` and the smoothers lock to the target values,
otherwise the phase accumulates per sample. A render starting at 30 s gives the same samples as the full render.
When the rate **changes along the song** (automation) `rate · pos` is no longer the right phase: at every start (seek,
block turned back on) the engine passes the processor the cycles run since the start of the song (`set_phase`),
computed in closed form from the rate lane the way the processor accumulates them, that is the value of each 32-sample
cell held for the cell (`Param::cycles` in `graph.rs`, one sum per lane segment). Verified property
in the engine: with ramps and steps on the tremolo and modulation rate, the render from 4 s, from 4 s + 17 samples
and from 70,001 gives the same samples as the full render (≤ 1e-4). A rate changed **by hand during playback**
continues from the accumulated phase, without a glitch, and becomes tied to the position again at the next start (A-090).

**Modulation (`Modulation`).** Sine LFO per channel, the right one offset by `spread_deg`; delay reads
with linear interpolation; output `dry·(1−mix) + wet·mix`. Chorus: 1–3 voices with bases 12/16/20 ms, delay
`base + depth·3 ms·lfo`. Flanger: delay `0.5 ms + depth·7.5 ms·(0.5+0.5·lfo)` with feedback (−0.9…0.9) in the line.
Phaser: 4/6/8/12 first-order all-passes `(a + z⁻¹)/(1 + a z⁻¹)`, `a = (t−1)/(t+1)`, `t = tan(π f/fs)`,
`f = 200 Hz · 20^(depth·(0.5+0.5·lfo))`, feedback of the chain output with one sample of delay. `depth`,
`mix`, `feedback` and the stereo offset are smoothed at 20 ms. Neutral: `mix` 0. Latency 0. Limit: with |feedback| ≤ 0.9
the wet path has gain ≤ 10.

**Tremolo and autopan (`Tremolo`).** Unipolar LFO `u = 0.5 + 0.5·lfo` (sine, triangle, square with smooth edges
`tanh(5 sin)/tanh(5)`). Tremolo: `gain = 1 − depth·(1 − u)`, right channel offset by `phase_deg`. Autopan: position
`depth·lfo`, angle `θ = (p+1)π/4`, `L' = √2 cosθ·L`, `R' = √2 sinθ·R`: constant power (gL² + gR² = 2), both
gains 1 at the center. Neutral: `depth` 0. Latency 0.

**Verified properties.** Phase rule (0–40 s against 30–40 s, comparison from 30.5 s, ≤ 1e-5), identity at neutral
(≤ 1e-6), block invariance (blocks of 32, 1000, 7: ≤ 1e-6), full-scale noise with extreme settings finite and
≤ 10.5, parameters changed every 32 samples stable, phaser notch that moves (> 6 dB of swing, 0 with depth 0),
tremolo envelope (4 Hz, depth 1: ≤ 1e-6), autopan constant power (≤ 1e-4) with energy alternating L/R.

## Width (`StereoWidth`, FX-19)

Mid/side: `M = (L+R)/2`, `S = (L−R)/2`, `S' = S·width` (0–2, smoothed at 20 ms), `L' = M+S'`, `R' = M−S'`. With
`mono_below_hz` > 0 the side first goes through a Linkwitz-Riley high-pass (two cascaded Butterworths, 24 dB/octave);
the frequency is smoothed and the coefficients redesigned every 32 samples counted from `reset`. At 0 the filter is excluded
(it keeps running at 1 Hz to keep the state warm). Neutral: `width` 1 and mono 0. Latency 0.

**Verified properties.** Identity at neutral (≤ 1e-6), `width` 0 ⇒ L = R, `width` 2 doubles the side (≤ 1e-6),
mono at 120 Hz: 50 Hz in the side attenuated ≥ 20 dB (LR4: about 30 dB), 1 kHz within 0.5 dB; input L = R unchanged at
any width (≤ 1e-6); block invariance; stability with parameters changing every 32 samples (≤ 2.5).

## Pitch: pitch shifter, harmonizer, doubler and shimmer (FX-21, FX-22, FX-24)

Files: `pitch.rs`, `reverb.rs`. No library; everything in f64, per sample, so the output does not depend on the block size.

### Pitch shifter (`PitchShifter`)

A delay line read by two taps whose delay slides over a window of `W` samples (35 ms in the harmonizer, 8 ms in the doubler, 20 ms in the shimmer). With ratio `r` each delay changes by `1 − r` samples per sample, so the read position advances by `r` and the pitch is multiplied by `r`. The sliding phase `φ` gives the delays `S + L·φ` and `S + L·frac(φ + ½)` and the weights `½(1 − cos 2πφ)` and `½(1 + cos 2πφ)`: they sum to 1 and the tap that jumps (at `φ = 0` or `½`) has weight 0 at that moment, so no click. Read with linear interpolation. The ratio is smoothed (10 ms).

**Tap alignment.** A simple crossfade gets the frequency wrong by several hertz: at every jump the output phase shifts by the phase difference between the two taps, at frequency `|1 − r| / L`. When a tap jumps (weight 0) its new delay is shifted by at most `±S` samples (`S = W/4`, `L = W − 2S`) onto the delay where its recent signal (`M = W/4` samples) has the highest normalized correlation with that of the other tap. Integer lags, deterministic, at contained cost (one search per jump). The search advances with step
`round(fs / 48 kHz)` both in the lags and in the compared samples: at 96 kHz the work of a jump is that of 48 kHz
instead of four times as much (A-090); at 44.1 and 48 kHz the step is 1 and nothing changes. Verified: at 96 kHz
the interval stays within 5 cents. At ratio 1 and `φ = 0` there are no jumps and the output is the input delayed by exactly `W/2`.

Own latency: mean delay `W/2` (`mean_delay()`).

### Harmonizer (`Harmonizer`)

The mono sum of the input feeds two voices: shifter of `semitones + cents` (±12 st, ±50 ct), level (−60…+12 dB), constant-power pan, summed to the dry with `mix` (0…1). Constant latency `Harmonizer::latency(rate)` = mean delay of the shifter rounded up to a multiple of 32 (864 samples at 48 kHz); the dry is delayed by that value, the voices by the remainder in addition. With `mix = 0` the output is the delayed dry, exactly. Parameters smoothed (20 ms) and set without gliding on the first call.

### Doubler (`Doubler`)

One or two copies of the input, detuned by `+detune` and `−detune` cents (shifter with 8 ms window, mean delay 4 ms), delayed by `delay_ms` (5–40 ms; the second voice ×1.25) with a slow drift of ±20% at 0.13 and 0.21 Hz, panned by `spread` (voice 1 left, voice 2 right), summed to the undelayed dry. Latency 0: the delay is the effect. Drift phase from the song position: if `pos` is not the frame following the previous call the phase is `frac(f·pos/rate)`, otherwise it accumulates.

### Shimmer (`Algorithm::Shimmer`)

The Hall network with a shifter (20 ms window) in the recirculation: the tail the network is about to return, shifted by `shimmer_semitones` (5, 7 or 12), re-enters the lines with weight `a/2` (`a = shimmer_amount`): `(1 − a/2)·feedback + a/2·shifted`. Since the shifted signal is a convex combination of the input samples, the loop gain does not exceed that of the Hall: bounded tail and exact silence at the end. At `a = 0` it is the Hall, sample by sample; Plate, Room and Hall know nothing of shimmer.

## Delay: ping-pong mode and tape character (FX-23)

Extension of the stereo delay (FX-6). With `mode = Stereo` and `character = Clean` the path is the original one,
unchanged: the output is bit-identical (golden checksum recorded with the previous code), whatever `wow` and
`drive_db` are, so the render hashes of existing projects do not change.

**New parameters.** `mode` (`Stereo`, `PingPong`), `character` (`Clean`, `Tape`), `wow` 0..1, `drive_db` 0..12 dB
(wow and drive act only with `Tape`).

**Algorithm.**
- `PingPong`: the input summed to mono `(L+R)/2` feeds only the left line; every repeat passes to the other
  channel (L, R, L, R…) with the same time and the same feedback filters (high-pass then low-pass).
- `Tape`: the time is modulated by wow (1 Hz, ±0.4% of the time) plus flutter (7 Hz, ±0.1%), both scaled by `wow`
  (smoothed like the time), read with linear interpolation. The phase of the LFOs depends only on the position in the
  song: `process_at(.., pos)` recomputes it as `frac(f·pos/rate)` on the first call and after every jump, otherwise
  it accumulates it; `process` uses an internal position that starts from 0 after `new`/`reset`.
- `drive_db`: soft saturation `tanh(g·x)/g`, `g = 10^(drive/20)`, on the feedback signal after the filters (unity
  gain for small signals, slope ≤ 1: the loop stays contractive). The value written is at most
  `|in| + 0.95/g`. `g` and `wow` are smoothed with the same low-pass as the time (50 ms).

**Verified properties.**
- Stereo/Clean: checksum identical to the original with `wow = 0, drive = 0` and with `wow = 1, drive = 12`.
- Ping-pong: the impulse gives alternating repeats L, R, L, R at multiples of the time (amplitude 0.5^(k−1) ±20%, other channel
  < 1e-3).
- Tape with `wow = 0` and `drive = 0` equal to the clean one (±1e-6).
- Wow: the render starting at 30 s coincides with the full one from 30.5 s onward (≤ 1e-5).
- Drive 12 dB, feedback 0.95, full-scale noise: bounded (< 1.3), in both modes.
- Block size independence (32, 1000, 7; ±1e-6) and parameters changed every 32 samples: finite and
  bounded (< 1.6 with drive ≥ 6 dB).
Latency: 0.
